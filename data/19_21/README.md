第18回までと同じスキーマで、第19回(2023)・第20回(2024)・第21回(2025)の
人妖・音楽・作品の各部門を整理し、`analyse_char.py` / Stanモデルに投入できる形式にした。

## データ取得方法（重要）
一次ソース `toho-vote.info` はJSレンダリングのSPAで、本環境では直接
スクレイピングできなかった。そのため同サイトを出典とし全回の票数・順位・
1位票数を保持する `maribelhearn.com/thvote`（MITソース, GitHub公開）の
PHPデータから char/music/works テーブルを抽出した（`raw_en/` に英語名で収録）。

## 英語名→日本語名の対応付け
maribelhearnは英語名、本リポジトリは日本語名のため、
**第18回の票数で自動照合**して対応表を構築（票数は両ソースで一致）。
- 人妖: 186件が双方向一意の票数で自動マッチ。同点クラスタ11ペアと
  希少キャラ2件(岩笠/沓頬の誤マッチ)を意味ベースで修正。全222名対応（衝突0）。
- 音楽: 第18回・第17回の2年票数ベクトルで578/614曲を自動マッチ。
  新曲は獣王園/錦上京のトラックリスト(Wikipedia等で検証)から手動補完。
- 対応表は `mapping/` に収録。

## ファイル構成
### by_poll/  — 回数別（各回・各部門の単独CSV）
`第19回_人妖.csv` 等。列: 順位, charid/名前(作品), 投票数, 一位票数, コメント数 等。
音楽は `登場作品` 列を付与。

### repo_format/ — 既存パイプライン投入用（第1〜21回を統合）
- `char_points_extended.csv`     行=回(1-21), 列=人妖名, 値=票数
- `char_points_ratio_extended.csv` charid,名前, 1〜21回の回内正規化比率（analyse_char.pyの主入力）
- `music_points_extended.csv`    music_points.csv に 19/20/21列を追加
- `title_points_extended.csv`    作品部門 12〜21回
- `Nchar_21.json`  Nchar=[25,...,268,270,278,279,283]（Nchar[-1]=283=総人妖数）

`analyse_char.py` は以下で動く想定:
```python
Nchar=[25,48,67,92,113,134,152,157,169,189,202,220,227,247,248,260,268,270,278,279,283]
# char_points_ratio.csv を char_points_ratio_extended.csv に差し替え、T=21 で実行
python analyse_char.py 21 5 prodsuminline
```

## 注意・既知の限界
- 一次の日本語ソースに直接アクセスできず、英訳経由で名寄せしている。
  人妖は全数検証済み。音楽の登場作品カバレッジは約84%で、残りは
  希少なCD/アレンジ曲（本リポジトリの music_title_re.csv 自体に未収録）。
- 一部の同人CD/書籍の作品名(100BM, Lotus Eaters 等)は英略称のまま残置。
- 票数・順位・1位票数の数値はソースのまま（高信頼）。誤差リスクは
  低得点の長い裾の名寄せに限定される。
